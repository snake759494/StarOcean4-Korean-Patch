## 2. 해독한 포맷

### 2.1 아카이브 `0001.bin` (34 GiB)

`KCAP` 팩 4,005개가 체인으로 연결. 0x800 정렬. 총 엔트리 129,631개.

```
pack header: "KCAP" | u32 ver(0x706) | u32 count | u32 total_size
entry (16B):  u16 id | u16 type | u32 unk | u32 usize | u32 offset
다음 팩 = (현재 팩 offset + total_size) 를 0x800 올림
```

`0000.bin` (12 GiB) 에는 KCAP 헤더가 없음. 폰트 사본도 없음(전수 검색 확인).

### 2.2 SLZ 압축

헤더 0x20바이트. `byte[3]` 이 변종(1/2/3). 청크 단위이며 **청크 원본 크기 = `hdr[0x19] << 10`** (0x10000).
각 청크 = `u16 clen` + 데이터. `clen == 0` 또는 `clen == 청크크기` 면 무압축 저장.
플래그는 LSB first, 비트 1 = 리터럴.

| 변종 | 방식 |
|---|---|
| v1 | 8비트 플래그, 바이트 리터럴. 매치 2바이트: `dist = b0\|((b1&0xf)<<8)`, `len = (b1>>4)+3`. dist 0 = 스트림 끝 |
| v2 | v1과 같되 길이 니블이 `0xf` 면 바이트 RLE로 이스케이프 (`dist<0x100`: fill=다음바이트, count=dist+0x13 / 아니면 fill=dist&0xff, count=(dist>>8)+3) |
| v3 | **16비트 워드 단위.** 16비트 플래그 워드, 리터럴 2바이트. 매치 워드: `dist = (raw&0xfff)` 워드 수, `len = (raw>>12)+2` 워드 |

`SLE` 매직은 같은 포맷을 XOR 난독화한 것 (키 16바이트, RVA `0xe91530`).
변종 분기 점프테이블은 RVA `0x3ee808`.

### 2.3 리소스 컨테이너

```
tag(4) | u32 size | 0 | 0
+0x10: "aRF " 블록 = 서브리소스 디렉터리 (tag / version / platform("ANY ","DX11"))
```

타입 4CC는 exe 레지스트리(RVA `0x90da00` 부근)에 이름과 함께 존재:
`AAI AAIA ACI ASF APF AAF AIF AIF2 AAIF PAIF ACF AAC AIR AMF AAR USER ...`

### 2.4 이미지 `AIF `

```
imgX 블록: +0x28 u16 W, u16 H / +0x3c u32 datasize
AMF  블록: 픽셀 데이터는 AMF_start + 0x1d0 부터
포맷: BC7 (fmt 코드 0x2e), 8 bits/pixel, 4x4 블록 16바이트
글리프 마스크는 알파 채널에 있음 (RGB는 0)
```

다른 포맷 코드: `0x10`=4bpp(BC1류), `0x12`/`0x14`/`0x15`=8bpp 블록압축. 비압축 8bpp 포맷은 없음.

### 2.5 텍스트 `MCDp`

```
+0x00 "pDCM" | +0x10 " dcm"
+0x18 부터 u32 섹션 오프셋 7개, +0x34 부터 u32 카운트 4개
 sect[0] 폰트 헤더 (nglyph, ascent, cellw, cellh)
 sect[2] 메시지 표: (u32 id, u32 offset) × cnt[2]
 sect[3] 텍스트 바이트
 sect[4] 글리프 표: {u32 advance, u32 (항상 0), float u0,v0,u1,v1} 24바이트
 sect[5] 텍스처 크기 (u32 w, u32 h)
 sect[6] 임베드된 AIF
```

**id=58 스토리 대사** — 텍스트는 **1-based 글리프 인덱스** 1바이트.
`00` 메시지 끝 / `80 80` 줄바꿈 / `93 80 <varid> 00 <기본이름> 00` 이름 변수.

**id=30 UI 문자열** — 자체 글리프 표 없음. **전역 문자셋의 2바이트 인덱스** 사용.
바이트 `<0x80` 은 직접 인덱스, `>=0x80` 이면 2바이트로 `value = b0 | (b1<<8)`.
라틴 구간: 공백=`0x0f80`, `A`~`Z` = 문자 + `0x0f5c`, `a`~`z` = 문자 + `0x0f56`.

### 2.6 언어 슬롯 (엔트리 type 하위 바이트로 구분)

| type | 언어 |
|---|---|
| 0x0223 | 일본어 |
| 0x0233 | 영어 |
| 0x0253 | 프랑스어 |
| 0x0263 | 독일어 |
| 0x0273 | 이탈리아어 |
| 0x0283 | 스페인어 |

폰트 팩(#668)에서는 끝자리가 1 (`0x0221` = JP 등).

### 2.7 텍스트 분량

- id=58 스토리: 183팩 / 10,595줄. **고유 씬은 97개** (86쌍이 중복 저장, 예: p38 == p2140)
- id=30 UI: 476팩 / 15,670줄 (JP 기준)
- 오프닝 컷신 대사는 id=58 에 **없음** — UI(전역 폰트) 경로로 추정

## 4. 시도했고 실패한 것

게임 화면에 한글을 띄우는 데 실패. 다음을 배제함:

1. **pack #668 폰트 8개 전부 한글 덧칠** → 화면 변화 없음.
   (JP 810글리프@2048², 나머지 192글리프@2048×512. 전부 압축·용량 통과, 파일 되읽기로 한글 아틀라스 확인)
2. **`0000.bin` 에 고해상도 사본** → 원본 폰트 픽셀 바이트로 12 GiB 전수 검색, **0건**.
3. **`sect[1]` 이 문자 코드 베이스** → 0/1 플래그일 뿐.
4. **슬롯 배열 순회 함수 추적** → 후보 62개, 노이즈 과다.
5. **제어코드 0x93/0x80 비교로 텍스트 해석기 탐색** → 해당 패턴 없음 (점프 테이블 방식 추정).
6. **24바이트 스트라이드 연산 함수** → 2개 발견했으나 폰트 스타일 배열 복사 루프였음.

### 핵심 모순

UI 문자 코드상 공백이 `0x0f80` = 3968. 즉 문자셋이 **4,000자 이상**이어야 하는데,
아카이브 전체에서 찾은 가장 큰 폰트는 **810글리프**. 진짜 UI 폰트를 아직 못 찾음.

pack #668은 `EXD`(스태프롤 UTF-16 텍스트)를 같이 담고 있고 글리프 배치 순서가
크레딧 문구 순서와 일치 → **엔딩 스태프롤 전용 폰트**로 보임.

## 5. 디스어셈블로 확정한 런타임 구조

exe 코드 섹션은 `.data1` (RVA 0x1000..0x90c000). DRM이 섹션명만 바꿨을 뿐 **암호화 안 됨**
(`.pdata` 가 이 범위를 함수 영역으로 가리킴). capstone으로 정상 디스어셈블 가능.

- `0x771ad0` — MCDp 등록. 매직 검사 후 매니저의 **슬롯 32개**(각 0x68바이트, base +0x210)에 등록
- `0x7a8e10` — MCDp 로더. 섹션→슬롯 매핑:
  `sect[0]→+0x20`, `sect[1]→+0x28`(및 `*sect[1]→+0x48`), `sect[2]→+0x30`, **`sect[4] 글리프표→+0x38`**, `sect[5]→+0x40`
- 등록 호출자 3곳: `0x771a20`, `0x771ba0`, `0x7a6a40`
- 호출자들은 exe 정적 테이블(RVA `0xa8f7d0`, `0xa97d08`)에서 설정값 5개를 읽어 슬롯 `+0x54`~`+0x64` 에 저장.
  값 세트는 `{1, 12, 14, 16, 33}` / `{0x761, 0x76c, 0x76e, -1, 0x77e}`
- `0x7a6a40` (UI 텍스트 서브시스템) 은 MCDp를 **2개만** 등록

## 8. 패치 적용 시 유의점

- 엔트리의 **byte span 안에 들어가면 인플레이스 패치 가능**. 디컴프레서가 청크 수를
  `usize` 로부터 계산하므로 뒤쪽 잔여 바이트는 절대 읽지 않음. 34 GiB 파일을 밀 필요 없음.
- 엔트리 `usize` 는 자유롭게 줄일 수 있음 (아틀라스 축소 시 유용).
- 동일 글리프가 반복되면 압축률이 크게 좋아짐 (실측: 원본 1,210,640 → 579,914).
- 스토리 팩은 2벌씩 중복 저장되어 있으므로 양쪽 다 패치해야 할 수 있음.
- 미번역 메시지는 **원본 글리프 비트맵을 새 아틀라스로 그대로 이식**하면 됨.
  일본어를 인식하지 않고도 부분 번역이 가능함.
